# Application Flow

## User Journeys

### Journey 1: Manager triggers manual run (SUPERVISED mode)

**Step 1: The Dashboard**
- **UI:** User visits `http://localhost:3000/dashboard`.
- **Backend:** Next.js calls `GET /runs`. FastAPI queries MongoDB `runs` collection.
- **UI:** Renders 4 KPI cards (avg PSI, success rate, etc.) and a table of the last 10 runs.

**Step 2: Initiation**
- **UI:** Manager clicks "Run Now". A modal appears.
- **UI:** Manager enters `https://my-demo.vercel.app`, selects `SUPERVISED`, clicks "Start Pipeline".

**Step 3: Trigger & Redirect**
- **Backend:** `POST /run` receives payload. Generates `run_id`, saves to MongoDB, starts `asyncio` task (`run_pipeline`) with a 2-second delay.
- **UI:** Receives `run_id`, redirects to `/live?run_id=...`.

**Step 4: Live View - Intelligence Layer**
- **UI:** `/live` mounts `useAgentStream` hook, connects to `GET /stream/{run_id}`.
- **Backend:** Pipeline starts. Layer 2 agents fire `agent_start` SSE.
- **UI:** The 4 Layer 2 Agent status blocks (teal color) pulse simultaneously.
- **Backend:** Agents complete, emit `agent_complete`. `merge_intelligence` node synchronizes.

**Step 5: Live View - Reasoning & Plan**
- **Backend:** `reasoning_agent` runs on Groq. Emits plan payload.
- **UI:** Right sidebar populates with "Metrics Profile", "Confidence Score", and "Plan Details".

**Step 6: Human Approval**
- **Backend:** `risk_classifier` flags as HIGH risk. Graph reaches `human_gate_node` and calls `interrupt()`. Emits `human_approval_required`.
- **UI:** The Executive Review Widget appears in the right sidebar.
- **UI:** Manager reviews diff preview and clicks "Approve".
- **Backend:** `POST /approve/{run_id}` resumes the LangGraph.

**Step 7: Gates & Sandbox**
- **Backend:** Fix agents generate code. Gates execute sequentially, emitting `gate_result` events.
- **UI:** Status icons in the Layer visualization swap from spinners to green checkmarks.
- **Backend:** `sandbox_agent` deploys to Vercel and tests PSI.

**Step 8: Deploy & Complete**
- **Backend:** `deploy_agent` opens GitHub PR. `report_agent` emits `run_complete`.
- **UI:** Pulse animations stop. Success banner shows PR link and ROI calculation.

### Journey 2: Automated scheduled run
Identical to Journey 1, except `RUN_MODE=AUTOMATED` skips Step 6 (`human_gate`). The PR is automatically merged if the sandbox tests pass. Triggered via APScheduler instead of UI.

### Journey 3: Sandbox rejects fix (no deployment)
At Step 7, if `sandbox_psi` is lower than `baseline_scores`, the `sandbox_agent` emits a FAIL `gate_result`. The graph routes to `sandbox_rejected` node. The PR is never created. UI shows amber "Skipped" status with explanation: "Sandbox PSI regressed by 4 points."

### Journey 4: Production regression triggers auto-revert
After deployment, if a separate background cron detects that the live site's PSI dropped by >5 points compared to the pre-run baseline, an emergency workflow is triggered. It uses GitHub API to revert the specific commit generated by the run, immediately triggering a Vercel production rollback.

## Agent Execution Flow

*Timings are approximate averages.*

```text
LAYER 2 [t=0s, parallel execution]:
  ├── metrics_agent: Fetches 5 pages from PSI API (~15-30s)
  ├── codebase_agent: GitHub file tree + preview extraction (~8s)
  ├── history_agent: MongoDB last 10 runs retrieval (~1s)
  └── context_agent: File map heuristic business scoring (~1s)

LAYER 3 [t=30s, sequential]:
  ├── reasoning_agent: Groq LLM inference for plan generation (~10s)
  └── risk_classifier: Pure Python matrix scoring (~0.1s)
  └── human_gate: [Variable pause until human API call]

LAYER 4 [t=40s, parallel]:
  ├── frontend_fix_agent: Groq LLM for React code diffs (~8s)
  └── backend_fix_agent: Groq LLM for API/Config diffs (~5s)

LAYER 5 [t=48s, sequential gates]:
  ├── syntax_gate: Regex secret scan + AST parse (~0.5s)
  ├── quality_gate: Complexity & line length heuristics (~0.5s)
  ├── critic_agent: Groq adversarial review (~5s)
  └── dependency_gate: Memory import graph traversal (~0.5s)

LAYER 6 [t=55s, sequential]:
  ├── sandbox_agent: Vercel Deploy + PSI check (~90-180s)
  └── deploy_agent: GitHub PR creation (~2s)

LAYER 7 [t=235s, parallel]:
  ├── learning_agent: Mongo fix_memory writes (~1s)
  └── report_agent: ROI estimation + run_complete SSE (~1s)
```

## Error Recovery Flows

- **Groq API 429 (Rate Limit):** `gemini_client` wrapper catches the error, applies exponential backoff, and eventually falls back to Gemini 2.5 Flash if Groq fails 3 times.
- **Gate Failure:** If `syntax_gate` or `quality_gate` fail, `retry_fix` increments `retry_count` in state. Routes back to Fix Generation. If `retry_count == 3`, graph routes to `skip_run`.
- **Sandbox Timeout:** If Vercel API doesn't return a "READY" status within 300s, `sandbox_agent` emits `FAIL`, graph routes to `sandbox_rejected`, run terminates gracefully.
- **SSE Disconnect:** `useAgentStream` on frontend automatically attempts reconnect via browser native `EventSource`. State is reconstructed from `agent_steps` array upon reconnect.
